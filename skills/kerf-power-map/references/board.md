# 視覺化與作戰圖指引

依 [SKILL.md 第 3 節](../SKILL.md#3-視覺化呈現與沿決定續作) 的交付範圍，在首次完整策略分析準備或需要製作、更新圖時讀取這份指引；已讀且仍適用時沿用。作戰圖要帶出證據支持的判斷，不是把使用者的計畫畫成流程：第 1 節的標題、對照、轉折點與錨點四項每張圖都必須具備，其餘形式依案情自行決定。

## 1. 決定畫什麼與呈現格式（對話圖優先，檔案按需）

- **標題是新判斷：** 寫使用者還沒說過、但證據支持的判斷，通常是盲點、漏洞或關鍵卡點。檢驗：不讀證據就寫得出這個標題，代表只是重述計畫，要重寫。
- **一組對照：** 呈現驅動推薦的兩件不一致的事，例如實際發生 vs. 拍板者看到、現況 vs. 擬議、誰拍板 vs. 誰被徵詢。選哪組自行判斷，但一定要有一組。
- **一個轉折點：** 標出第一步要改變的那個節點、格或連線，推薦行動要明顯指回它。
- **本案錨點：** 每個元素帶一個本案具體錨點（日期、數字、文件或原話）與第 2 節的證據標籤。
- **量化或簡報成品交給圖表 skill：** 判斷建立在數字上（金額影響、工時、版本增量），或使用者要的是月會簡報、報告等成品時，改用已安裝的簡報／圖表 skill（如 kerf-clayprint）製作，本圖只保留關係與判斷。
- **形式自行決定：** 結構（表格、泳道、網絡、分支樹……）、畫進哪些人或層級、視覺編碼、是否加換路信號、手機是否拆視圖，都依案情選擇；兩人局或局部問題只畫相關關係，不為湊版面虛構人物。
- **優先在同一回覆呈現對話圖：** 使用環境支援的 Mermaid、內嵌 SVG 或對話內視覺工具（如 `html_preview` / `html_render`）。使用者追問「什麼時候要視覺化／給我看圖」時，直接在當前回覆呈現已驗收且仍適用的對話圖並簡短指出主線（有新資訊或閱讀缺口時更新重驗），不要只回「前面畫過了」或擅自改成匯出獨立檔案。
- **獨立交付檔案只在明確要求時建立：** 使用者明確要求產出完整報告、可下載／儲存離線 HTML 作戰圖時，才建立並保留獨立交付檔案（不依賴 Python、固定 JSON schema 或外部網路資源）。未要求匯出時，若對話內格式太複雜，應拆成聚焦的對話視圖或結構化對照，不主動輸出獨立 HTML 交付檔。
- **臨時預覽不等於交付：** 若需透過臨時本機檔案完成渲染與雙寬度驗收，僅在**使用者未限制「不建立檔案」**時可用，且不得當成未經請求的交付物；使用者一旦明說「不建檔／不建立檔案」，一律不寫入任何檔案，直接在當回合給出可讀的對話內關係圖或結構化文字對照，並誠實說明因此未執行的視覺渲染檢查。

## 2. 圖形不能扭曲證據紀律

- **分清事實、單方描述與推測／未知：** 文件紀錄、使用者轉述與推測以圖例或簡短標註區分，不必每個詞重複貼標籤。書中案例類比用註解連到判斷，不畫成本案已發生的事實。
- **分清不同性質的連線：** 正式匯報、實質影響力、依賴、日常寄信／抄送（CC）路徑、與衝突要分別標明——寄信給某人不等於能影響他，收到副本也不等於未參與。
- **隸屬方向不依稱謂推定：** 「主管」等未標明方向的稱謂，在文件（誰交辦誰）或使用者確認前，上下隸屬畫成未知。
- **立場與行動分清「現況」與「目標」：** 未知立場單獨標示並連到查證或條件分支，絕不放進「反對 ↔ 中立 ↔ 支持」中間猜成中立；擬議的未來行動與已發生的事分開標示。
- **硬限制與退路定義準確：** 上級定死的安排（環境固定限制）與使用者個人紅線用不同標記；獨立退路（BATNA）與仍需同一批核准者同意的縮小試點分開標示。
- **貢獻對照看實質增量：** 保留版本、實際新增內容與適用範圍；視覺面積、線條粗細與顏色只表達有證據支持的差異，不捏造功勞百分比。

## 3. 版面美學與離線安全

- **設計方向：** 對話內渲染不設整頁背景、沿用環境主題變數；沿用專案或使用者既有設計方向；無指定方向時，避開米白／奶油背景、標題斜體強調、裝飾性數字段落標籤（`01/02`）、monospace 標籤與膠囊按鈕。
- **離線與資安：** 獨立 HTML 僅用內嵌 CSS、SVG、表格與必要的本機互動腳本，零遠端字型／CDN／外連追蹤。引用信件與文件文字須適當跳脫（Escape），不順手嵌入資料夾內其他私人檔案。

## 4. 內容與雙寬度視覺驗收

- **續作局部更新：** 以既有圖為底，只改新事實影響的標註、連線與行動；未受影響的權限、目標與退路保留原位。無法直接修改既有圖時，交付可對照原圖位置的局部替換圖，不藉續作重排整張圖。
- **判斷檢驗：** 遮住文字回覆只看圖，要答得出誰拍板、卡在哪、第一步做什麼；這張圖換到別的案子還能照用，就重做。常見失敗：流程方塊加箭頭重述使用者計畫；所有人畫成同大小方塊、看不出權力差；證據標籤只放註腳。另沿重要連線核對人物、方向、權限、利益、依賴與來源，確認圖與推薦路徑一致。
- **視覺實看（桌面與手機）：** 環境有 `html_preview` 時，以 `width=728` 與 `width=375` 各預覽一次並實際看截圖；檢查長姓名與標籤是否截斷、線條與箭頭是否重疊、有無隱藏水平溢出，修正後重看受影響部分。手機版應重排或拆視圖，不把整張桌面圖硬縮；關鍵資訊不只靠顏色或滑鼠懸停（Hover）。
- **誠實交代驗收範圍：** 交付時簡述已完成的內容與視覺檢查。檔案存在、Mermaid 原碼或結構檢查只算製作狀態，**實際渲染觀看才算完成視覺驗收**；若工具、權限或「不建檔」限制使渲染預覽受阻，當回合直接交出可讀的對話關係圖或文字對照，並明確列出受阻原因與未驗證的視覺項目。
